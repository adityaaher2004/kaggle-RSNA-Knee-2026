----------------------------------------
R1. specs.txt is the source of truth. Numbers that code consumes live in
    configs/*.yaml and are tagged here as  [cfg: key.path]. A change to a
    [cfg] value is made in the YAML, then reflected here in the same commit.

    first, then code is changed to match. Every module docstring starts with
    "SPEC: Sx.y" pointing at the section it implements. tests/test_spec_sync.py
    fails if a module's SPEC tag points at a section that no longer exists or
    a [cfg] key named here is missing from configs/base.yaml.
R3. Every claim is tagged:
      [V]  verified on local data / files / machine (date in S0)
      [W]  from the web, secondary source (competitor repo/blog) -- must be
           re-checked against the Kaggle page before it drives a decision
      [E]  established method from the literature (cite in S15)
      [H]  hypothesis -- must pass an ablation (S12) before it stays
    Nothing tagged [H] ships in the final model without an ablation win.
R4. Nothing that is unavailable at test time (report text, labels, report-
    derived features) may enter the inference path. Enforced by
    tests/test_leak.py (T-LEAK-1).
R5. Deadline rule: the final deadline is 2026-10-22 [W]. Any item that cannot
    produce a measured result before 2026-10-20 is DEFERRED (S16), however
    attractive. Ship a scored submission early; improve from there.

S1. PROBLEM FORMULATION
--------------------------------------------------------------------------------
Hierarchy: study i -> series j = 1..m_i (3..14) -> slices k = 1..n_ij.
Train tuple (X_i, M_i, T_i, y_i), y_i in {0,1}^12 for 58 studies, missing for
4,349. Test tuple (X_i, M_i): M_j = (plane, contrast) is in test_series.csv
[V-old: present in the local test_series.csv], so the student MAY use it.
We learn p(y | X, M) with 12 sigmoids. Training targets for the 4,349 come
from q(y | T) (the report labeler), so the image model learns
     min_theta  E_i  sum_l  CE( q_l(T_i) , p_theta,l(X_i, M_i) )
which is exactly logit/probability distillation from a text-only teacher
into an image-only student (Hinton 2015 [E]; LUPI, Vapnik 2009 [E]). The 58
gold studies are kept out of training and used only to measure p vs truth.

S3. DATA PIPELINE  (DICOM treated as part of the model)
--------------------------------------------------------------------------------
S3.1 Loading (data/dicom.py)  [E]
  - pydicom.dcmread(stop_before_pixels=True) for all headers first; pixels
    decoded with pydicom + pylibjpeg (libjpeg: JPEG Lossless; openjpeg:
    JPEG 2000); fallback chain pylibjpeg -> GDCM (python-gdcm) -> SimpleITK;
    log which decoder was used. A series where >10% of slices fail is
    marked bad and excluded (inference: study gets the prior, S13).
  - Apply RescaleSlope/Intercept if present. Use float32 until windowing.
  - Read: ImagePositionPatient (IPP), ImageOrientationPatient (IOP),
    PixelSpacing, SliceThickness, SpacingBetweenSlices, Rows, Columns,
    InstanceNumber, Manufacturer, ManufacturerModelName,
    MagneticFieldStrength, TransferSyntaxUID, EchoTime, RepetitionTime.
  - Why filename sort is unsafe: filenames are SOPInstanceUIDs (random
    1.2.826.0.1.3680043.8.498.<digits> strings [V]); lexical order has no
    relation to anatomy. InstanceNumber is usually but not always monotone
    in position; SliceLocation sign conventions vary by vendor.
S3.2 Geometry (data/geometry.py)
  - normal n = cross(IOP[:3], IOP[3:]); key_k = dot(IPP_k, n); sort by key.
    Fallbacks (logged): InstanceNumber, then SliceLocation.
  - Drop duplicate positions (|dkey| < 1e-3 mm; keep the later
    InstanceNumber) and localizer slices whose IOP differs from the series
    mode IOP.
  - Canonical orientation [H-recipe, E-principle]: per plane, flip/transpose
    the 2D arrays so that image rows/cols map to fixed patient axes
    (sagittal: rows S->I, cols A->P; coronal: rows S->I, cols R->L patient;
    axial: rows A->P, cols R->L). Laterality: we do NOT mirror left knees
    to right; medial/lateral labels are anatomical, and a left knee in
    canonical patient-axes orientation shows medial on the other side.
    Add a `side` flag (from the sign of the patient-x coordinate of the volume
    centre) to the metadata; whether to mirror left knees to a right-knee
    frame is ablation A13.
  - In-plane resampling to 0.6 mm (cv2.INTER_AREA when downsampling), then
    centre crop / zero-pad to 256 x 256 px = 153.6 mm FOV [cfg:
    data.spacing_mm, data.size]. Centre = centre of the foreground mask
    (Otsu on the middle slice), not the image centre [H].
  - Through-plane: NO interpolation (thickness 2.5-4 mm vs 0.6 mm in-plane
    is ~5x anisotropic; interpolation invents data). Keep native slices;
    store at most 48 central slices [cfg: data.max_slices_store].
S3.3 Intensity
  - Per-series percentile window [p1, p99.5] over the foreground voxels,
    scale to uint8 [cfg: data.pct]. No cross-series normalisation.
  - At load: uint8 -> float, /255, then (x - 0.5)/0.25 (backbone-agnostic).
S3.4 Cache format
  - One npz per series: vol uint8 (n<=48, 256, 256), z_mm float32 (n),
    plus a json sidecar with header fields. ~24k files, est. 40-60 GB.
  - Recipe version string stored in each file (cache/v1). Any change in S3
    bumps the version and rebuilds; train and Kaggle use the same version.
  - Parity test (tests/test_parity.py): run the HPC pipeline and the Kaggle
    kernel's code path on the same 15 test series; max |diff| == 0.
S3.5 2.5D windows (data/dataset.py)
  - A window is 3 consecutive slices (k-1, k, k+1) of one series -> 3
    channels; edges replicate.
  - Train: per series, T=10 window centres sampled by stratified jitter
    across the slab (divide [0,n) into T bins, pick a random centre per bin).
    Eval/test: T_eval = 16 evenly spaced centres (covers ~all slices of a
    30-slice series) [cfg: data.t_train, data.t_eval]; models are
    position-embedded by physical z so T may differ train vs test [H, A14].
  - Window z-position = (z_k - z_mid)/150 mm (normalised physical offset).
S3.6 Series selection (data/series_select.py)
  - S_max = 6 [cfg: data.s_max]. Priority: (1) one fluid-sensitive series
    per plane (sag, cor, ax); (2) one non-fluid series per plane (sag, cor
    first); (3) remaining by slice count desc. Ties -> SeriesInstanceUID
    order (deterministic).
  - Train: with prob 0.5 sample a random subset of size in [3, S_max]
    instead (series dropout), never dropping all fluid-sensitive series.
  - Padded series/windows masked in attention and pooling.
S3.7 Augmentation (data/augment.py; train only; same params for all windows
     of one series)
  - RandomResizedCrop scale [0.8, 1.0], ratio [0.9, 1.1]; rotate +-10 deg;
    translate +-6%; brightness/contrast +-0.15; gamma [0.8, 1.25]; gaussian
    noise sigma <= 0.03; blur p=0.1. Slice-order reversal: NO (z-position
    embedding must keep meaning).
  - NO horizontal or vertical flips (they swap medial/lateral or
    anterior/posterior without changing labels) [E: competitor consensus,
    anatomy].

S4. TENSOR SHAPES  (shipped Reader; B = studies per micro-batch, S = 6 series,
                    T = 10 train / 16 eval windows, d = 384, L = 12 labels)
--------------------------------------------------------------------------------
 x          : B x S x T x 3 x 256 x 256        float16/bf16 (B=4 -> 240 imgs)
 win_mask   : B x S x T  bool   (False = padded window)
 ser_mask   : B x S      bool
 z_pos      : B x S x T  float  (normalised mm offset, S3.5)
 plane      : B x S      int in {0 sag, 1 cor, 2 ax}
 contrast   : B x S      int in {0 non-fluid, 1 fluid-sensitive/fat-sat}
 flatten                       : (B*S*T) x 3 x 256 x 256
 backbone (EffNetV2-S) fmap    : (B*S*T) x 1280 x 8 x 8
 GeM pool (p=3 learnable)      : (B*S*T) x 1280
 Linear(1280->384) + LayerNorm : (B*S*T) x 384  -> B x S x T x 384
 + E_z(z_pos) + E_plane + E_contrast + E_series(j)   (S7.2)
 reshape to study tokens       : B x (S*T = 60) x 384,  key_padding = ~mask
 study transformer (2L, 6 heads, ff 1536, pre-LN, drop 0.1)
                               : B x 60 x 384
 label-query head: Q (12 x 384) cross-attends tokens (1 layer, 6 heads)
                               : attn A  B x 12 x 60 ; H  B x 12 x 384
 per-label classifier w_l . H_l + b_l  (b_l init = logit(prior_l))
                               : logits B x 12
 Params: backbone ~20.2M (EffNetV2-S w/o classifier) + heads ~4.3M.
 Stage A cache: per window 1280-d fp16 -> 24k series x 16 win x 1280 x 2 B
                ~ 1.0 GB (fits in RAM).

S5. SUPERVISION SOURCES
--------------------------------------------------------------------------------
Tier G (gold, 58)  : NEVER trained on in CV runs. Each gold study is scored
                     only by the fold model that held it out (fixes the
                     leakage seen in the 18th-place write-up [W]). Used for
                     model selection, labeler selection, ensemble weights.
Tier R (report, 4,349): soft targets q in [0,1]^12 from S6, with per-slot
                     confidence c in [0,1]. Slot with labeler status
                     "uncertain" -> q=0.5*prior+..., see S6.4; status
                     "not_mentioned" -> q = learned "silence prior" per
                     label (radiologists rarely mention absent minor
                     findings; not-mentioned ~= absent for Baker's/
                     Fracture, not for OA) [H, measured on gold].
Final submission models: trained on all 4,349 Tier R (no CV hold-out) only
                     if a fold-ensemble vs full-fit comparison on gold-OOF
                     is not possible in time -> default ships the 5 fold
                     models (gold-OOF is then an honest estimate).
Caveat: Tier-R label-OOF AUC measures agreement with the labeler, not truth;
        it is always printed next to gold-OOF AUC with a 95% bootstrap CI
        (n=58 -> CI width ~ +-0.05 per label, ~ +-0.02 macro [H]).

S6. RADIOLOGY NLP  (labels/)  -- the "teacher" of this system
--------------------------------------------------------------------------------
S6.1 Decision: structured per-finding extraction, not full-report embedding.
  The targets are 12 named findings; errors come from negation, hedging,
  laterality (medial vs lateral), compartment (PF OA), severity thresholds
  (when is chondral thinning "OA"?), and ~12 languages. An instruction-
  tuned multilingual LLM handles all of these with no translation stage and
  can be audited per slot against gold; XLM-R embeddings cannot produce the
  labels without supervised fine-tuning, which 58 gold rows cannot support.
S6.2 Primary labeler (labels/llm_labeler.py)  [E: LLM report labelling
  is an established practice; specific model choice H]
  - Run locally on 1x H100 (80 GB) with vLLM, temperature 0, JSON-schema
    constrained decoding. Candidates (check licence + "publicly available"
    rule, T-RULES-2): Qwen3-family ~30B MoE instruct; Gemma-3-27B-it;
    MedGemma-27B-text; Llama-3.3-70B-Instruct (AWQ int4) as the slower
    second opinion [cfg labels_llm.yaml: labels.model]. Pick by gold macro-AUC, not by
    reputation.
  - Output per finding: status in {present, absent, uncertain,
    not_mentioned}, probability p in [0,1], evidence quote (verbatim,
    original language). Prompt defines each label precisely (e.g. "Medial
    OA = cartilage loss/osteophytes/subchondral change of the medial
    femorotibial compartment; isolated chondromalacia grade I = absent";
    "Contusion = bone marrow oedema/bruise not due to OA"), with negation
    and hedging rules and 1 short example per language family.
  - Budget: 4,407 reports x ~1.2k prompt + 0.4k output tokens ~ 7M tokens;
    a 30B MoE on vLLM does this in < 1 h on one H100 [H].
  - Self-consistency (optional): 3 prompt paraphrases, average p.
S6.3 Rule extractor (labels/rules_extractor.py): lexicon + NegEx windows for
  en, es, de, nl, tr (top languages). Purpose: catch LLM failures (big
  disagreement => manual review list), not to produce labels. Low priority.
S6.4 Fusion (labels/fuse.py)
  - Sources: our labeler(s) and, if the rules allow it (T-RULES-2), public
    Kaggle label datasets released by other teams [W: these exist].
  - Per label l: q_l = sigmoid( sum_s a_{s,l} logit(p_{s,l}) + b_l ),
    a, b fitted by L2-regularised logistic regression on gold (58), with a
    strong prior a = 1/n_sources, b = 0 (lambda chosen by leave-one-out).
    If gold support for a label is < 10 positives (MCL, Baker's, LatOA),
    keep the prior weights (no fit).
  - Confidence c_l = 1 - normalised std of sources (agreement).
S6.5 Gold evaluation (labels/gold_eval.py): per-label AUC, AP, precision at
  0.5; per-language breakdown (n per language per label is tiny -> report
  counts, not just ratios). Gate: a label set is adopted if its gold macro
  AUC beats the current one; no per-slot masking unless a slot's gold AUC
  < 0.7 (then train that slot at weight 0.3).
S6.6 Leakage control: the labeler prompt and fusion weights are frozen
  before image models are compared; prompt files are versioned and never
  edited in place.

--------------------------------------------------------------------------------
S7. MODEL ARCHITECTURE  "OxAlpha Reader" (shipped)  + deferred teacher
--------------------------------------------------------------------------------
Design summary: 2.5D window encoder -> one transformer over ALL windows of
ALL series of a study (with physical-position, plane and contrast tokens)
-> 12 label queries that each attend to the windows they need. This merges
the 0.1.0 design's slice-MIL, series transformer and label head into one
cheaper block, and keeps per-label attention for error analysis.

S7.1 Window encoder (models/slice_encoder.py)
  Primary: EfficientNetV2-S, timm `tf_efficientnetv2_s.in21k_ft_in1k`
  (ImageNet-21k pretrained), 3-channel 2.5D input, GeM pooling, -> d=384.
  [cfg: slice.backbone, slice.d]. Drop-path 0.1, dropout 0.2.
  Why this over the alternatives:
    2D CNN per slice (no 2.5D)   : loses through-plane context for thin
                                   tears; 2.5D is free (3 channels).
    3D CNN / Swin-3D / SwinUNETR : ~5x anisotropy and 3-14 differently
                                   oriented series per study break the 3D
                                   prior; no ImageNet-scale 3D weights;
                                   memory heavy. Not in 8 days.
    ViT-B / DINOv2 2D            : strong features but 256px x 240 imgs per
                                   step is costly; candidate for Stage A
                                   frozen-feature ablation A11 only.
    MRI-specific SSL encoders    : no verified public knee-MRI weights.
    ConvNeXt-T (28M)             : second family for ensemble diversity
                                   (public reader at 0.929 uses ConvNeXt [W]).
  Gradient checkpointing on backbone stages; BN kept in train mode (batch of
  240 images is large enough).
S7.2 Token embeddings (models/embeddings.py)
  E_z     : MLP(Fourier features of z_pos, 16 freqs) -> 384
  E_plane : Embedding(3, 384);  E_contrast : Embedding(2, 384)
  E_series: Embedding(S_max, 384) indexed by the PRIORITY SLOT of the series
            (slot 0 = fluid sag, ...), not csv order -> carries "which kind
            of series" consistently.  Decision on z_j = f(V_j, M_j) vs
            f(V_j): use f(V_j, M_j). Reason: visibility of each finding
            depends on plane and contrast (menisci/ACL: sagittal; MCL:
            coronal; PF OA: axial/sagittal; oedema/effusion: fluid-
            sensitive), metadata is present at test time, and it costs 2
            embeddings. Ablation A4 checks it.
S7.3 Study transformer (models/series_encoder.py)
  2 pre-LN encoder layers, d=384, 6 heads, ff 1536, dropout 0.1,
  key-padding mask. Full attention over S*T <= 96 tokens is cheap.
  [cfg: series.layers, series.heads, series.ff, series.drop]
S7.4 Label-query head (models/heads.py)  [E: Query2Label (Liu 2021),
  ML-Decoder (Ridnik 2023), adapted: queries attend over MRI window tokens
  instead of 2D spatial tokens]
  12 learned queries; 1 decoder layer (cross-attn + FFN, no query self-attn
  in v1 [H: self-attn among queries = cheap label-dependency modelling,
  ablation A10]); per-label linear classifier; bias init logit(prior).
  Attention A (B x 12 x 60) is logged for error analysis only (attention is
  not an explanation, S14 F-8).
S7.5 Aggregation alternatives (models/mil.py) -- kept as ablations
  mean pool      : baseline; dilutes focal findings (tear on 2 of 30 slices).
  max pool       : good for focal findings, noisy; won the 18th-place search
                   [W] -> must be in our table (A1).
  gated attention MIL (Ilse 2018 [E]): one bag level; needs a separate
                   series aggregator; equivalent to our head with 1 query.
  DSMIL / CLAM   : need instance-level pseudo-labels or clustering; little
                   gain expected with 60 instances/study; not built.
  TransMIL       : = our study transformer without label queries.
S7.6 Label structure / GNN -- DECISION: NO GNN.
  12 nodes; the only exact labels are 58 rows; co-occurrence in report
  labels reflects report style as much as anatomy. Expected benefit is
  below gold-AUC noise (~+-0.02). Cheap substitute: query self-attention
  (A10). Notebook 02 still measures phi/conditional probabilities (e.g.
  MedMen-MedOA, Effusion-Synovitis, ACL-Contusion are clinically expected
  pairs).
S7.7 Multimodal teacher -- DEFERRED (post-v1, only if days remain)
  Design kept from 0.1.0, restated: image trunk + XLM-R-base report embedding
  -> fusion MLP -> 12 logits, modality dropout p_text=0.3, ITC (InfoNCE)
  between z_study and z_text; then offline KD (logit tau=3 + feature cosine)
  into the Reader. Why deferred: (a) the labeler already gives the
  text-only teacher's predictive distribution (S1); (b) a fused teacher
  trained on report-derived labels learns to copy the report (leakage F-2),
  so its extra value is only where image evidence corrects the report;
  (c) cost > 2 days. A cheaper variant of (c) is Stage B2 (S9): use
  image-model OOF predictions to refine the targets.
S7.8 Anatomy-aware modelling: v1 = global model + per-label queries
  (learned soft localisation). No segmentation / ROI proposals (no masks).
  Foreground-centred crop (S3.2) is the only anatomy prior.

--------------------------------------------------------------------------------
S8. LOSS FUNCTION
--------------------------------------------------------------------------------
L = l1 L_diag + l2 L_KD + l5 L_aux        (L_feat, L_ITC, L_attn: DEFERRED)
  L_diag : soft-target BCE, sum over labels of
           w_l * c_il * BCE(q_il, sigmoid(s_il)),
           w_l = 1 (macro AUC weighs labels equally; per-label pos_weight
           does not change AUC-optimal ranking much) [cfg: loss.label_w].
           Ablations: hard targets (q > 0.5), ASL (gamma_neg 4, clip 0.05,
           Ridnik 2021 [E]) on hard targets.
  L_KD   : Stage B2 only: BCE(q~_il, s_il) with q~ = 0.5 q + 0.5 sigma(s^OOF)
           (OOF ensemble of Stage B models) [H; noisy-student / self-
           distillation, Xie 2020 [E]]. Implemented as a target change, so
           L_diag and L_KD collapse into one term with mixed targets.
  L_aux  : attention-entropy regulariser on head attention, l5 = 0.01, only
           if attention collapses to one window (monitored) [H].
  Plane/contrast prediction: NOT used (metadata is an input, so predicting
  it is trivial).
Weights: l1 = 1, l2 = 0 (Stage B) / mixing 0.5 in B2 [cfg: loss.*].
Selection: coordinate search on gold-OOF macro AUC at 2 folds; final value
  must not hurt label-OOF by > 0.005.

S9. TRAINING SYSTEM  (IU HPC, 1x H100 80 GB per job)
--------------------------------------------------------------------------------
Stage A (frozen features, build FIRST, minutes per run):
  cache_features.py runs EffNetV2-S (ImageNet weights, no finetune) over
  T_eval=16 windows of every cached series -> 1280-d fp16. Heads (S7.2-S7.5)
  train on the cache. Used for: label-set comparison (S6.5), aggregation
  ablations A1-A4, A10. Each run < 10 min on CPU/GPU.
Stage B (end-to-end Reader, the shipped model):
  AdamW (0.9, 0.999), wd 0.05; lr backbone 2e-4, heads 1e-3 (scaled for an
  effective batch of 32 studies); layer-wise decay 0.85; 1 epoch linear
  warm-up then cosine to 1e-6; 12 epochs [cfg: train.*]; micro-batch 4
  studies, accum 8 -> 32; grad clip 1.0; bf16 autocast (H100); EMA 0.999,
  evaluate EMA weights; channels_last; torch.compile if it works on 2.14.
  Throughput estimate [H]: ~4.4k studies x 60 windows = 264k images/epoch;
  EffNetV2-S 256px fwd+bwd ~ 2.5k img/s on H100 bf16 -> ~2 min/epoch of
  GPU compute; the real limit is npz loading -> 16 dataloader workers,
  npz kept uncompressed (np.savez) or memmapped. Expect < 1 h per fold.
  Data loader: whole cache (~50 GB) staged to node-local /tmp if present.
Stage B2 (label refinement, if Stage B works by day 5): retrain with mixed
  targets (S8 L_KD) using the 5-fold OOF predictions from B. Accept only if
  gold-OOF improves.
Stage C: DEFERRED (S7.7).
Seeds: fold assignment seed 42 fixed forever [cfg: seed]; model seeds 0,1,2.
Logging: per-epoch macro + per-label AUC (label-OOF; gold-OOF of the
  held-out fold), loss, lr, grad norm, attention entropy, throughput,
  peak GPU memory. Each run dir stores the config, git commit hash, spec
  version, cache version, label-set version.
Slurm: scripts/slurm/train_fold.sbatch, --array=0-4, partition
  h100-single, --gres=gpu:1, --cpus-per-task 16, --mem 128G, time 06:00:00.

S10. VALIDATION  (validation/)
--------------------------------------------------------------------------------
- Unit of split = study; series/slices are never split.
- Site grouping (validation/sites.py): no site column exists [V-old]. Proxy
  cluster = (Manufacturer, ManufacturerModelName, MagneticFieldStrength,
  report language, rounded PixelSpacing/Rows); merge rare clusters
  (< 20 studies) into "other". Competitors found random folds overstate CV
  by ~0.05 [W] -> grouped folds are mandatory.
- Duplicates (validation/dedup.py): identical or near-identical reports
  (MinHash Jaccard >= 0.8 on character 5-grams) or near-identical image
  features (cosine >= 0.98, Stage A mean feature) -> same group.
- Folds (validation/folds.py): 5 folds, groups = site cluster U dup cluster
  (multilabel-stratified group k-fold: iterative stratification on the
  binarised report labels, Sechidis 2011 [E], applied at group level).
  The 58 gold studies are spread ~11-12 per fold (stratified on gold
  labels). Written once to folds.csv with a checksum; every experiment
  reads it.
- Two numbers per experiment: gold-OOF macro AUC (58 studies, each predicted
  by its held-out fold model) with bootstrap CI, and label-OOF macro AUC
  (4,349, vs binarised fused labels).
- Ensemble weights fitted on OOF only.

--------------------------------------------------------------------------------
S11. EVALUATION AND CALIBRATION
--------------------------------------------------------------------------------
- Metric: macro mean of 12 per-label ROC-AUCs over the test studies. AUC is
  rank-based per label: monotone transforms of one label's scores do not
  change it; calibration and thresholds are irrelevant to the score.
  Accuracy/F1 at 0.5 are misaligned (prevalences differ per label and
  between sources).
- Consequences: (a) per-label rank averaging is safe for ensembling;
  (b) a label is worth 1/12 regardless of prevalence -> rare labels (MCL,
  Baker's, LatOA) matter as much as Effusion; (c) a "neutral 0.5" fallback
  for a failed study is the safest output (S13).
- Calibration (ECE) is logged only for sanity (detects collapsed heads).
- Co-occurrence analysis in notebook 02 informs S7.6 only.

S13. INFERENCE, ENSEMBLE, SUBMISSION  (inference/, kaggle/)
--------------------------------------------------------------------------------
- Kernel: offline. Code + weights uploaded as Kaggle datasets; wheels for
  timm, pydicom, pylibjpeg, pylibjpeg-libjpeg, pylibjpeg-openjpeg,
  python-gdcm built for the Kaggle image's Python (kaggle/build_wheels.sh).
- Per test study: read headers -> select series (S3.6) -> preprocess with
  the identical cache v1 code -> T_eval=16 windows -> models -> 12 probs.
- Time budget for ~1,300 studies x ~5.5 series [H]: DICOM decode is the
  bottleneck (JPEG 2000 ~20-50 ms/slice). 4 CPU workers decode while the GPU
  runs models (producer/consumer). Target total < 3 h for 5 folds x 2
  families; hard guard: inference/predict.py measures elapsed time and
  degrades (fewer windows 16->10, then fewer models) if projected > 7.5 h.
- Robustness: try/except per series and per study; a study with no usable
  series gets per-label training priors (any constant is AUC-neutral);
  submission.csv written incrementally every 50 studies.
- TTA: identity + 1 scale crop (0.9) [H, A-table]. No flips.
- Ensembling: average logits over folds/seeds of one family; rank-average
  per label across families and external public models (if blended).
  Weights from OOF where available; equal weights otherwise.
- Efficiency track [W]: a single fold EffNetV2-S with T_eval=10 is the
  natural entry; secondary goal, only if free.

S14. FAILURE MODES AND MITIGATIONS
--------------------------------------------------------------------------------
F-1  Report labels wrong (negation, hedging, language) -> LLM with explicit
     rules, gold evaluation per label, fusion with other sources, per-slot
     confidence weights.
F-2  Leakage of report into the image path (multimodal teacher copies the
     report) -> teacher deferred; T-LEAK-1 test; Reader has no text inputs.
F-3  Gold leakage into training -> gold never trained in CV; each gold
     study scored by its held-out fold only (T-SPLIT-1).
F-4  Wrong slice order -> IPP projection sort; T-ORD-1 shuffles files.
F-5  Train/test preprocessing mismatch -> one shared function, cache
     version string, T-PARITY-1 on the 15 local test series.
F-6  DICOM decode failure in the kernel (JPEG 2000 / lossless) -> decoder
     fallback chain, offline wheels tested in a Kaggle dry-run, neutral
     prior output for failed studies.
F-7  Anisotropy (0.25 mm in-plane vs 3-4 mm slices) -> 2D/2.5D encoder, no
     through-plane interpolation, physical z embedding.
F-8  Attention taken as explanation -> attention used only to pick cases
     for review; occlusion of windows to test whether predictions change.
F-9  Irrelevant series (localisers, T1 without fat-sat) -> priority
     selection, plane/contrast tokens, series dropout.
F-10 Small findings lost (tears span 1-2 slices; 256 px crop) -> 2.5D,
     T_eval 16 covering all slices, B4 resolution ablation, label queries.
F-11 Class imbalance per label (MCL 9/58) -> macro AUC is insensitive to
     balancing; rely on soft targets; bias init to prior; monitor
     per-label AUC, not loss.
F-12 Overfitting (4.4k studies) -> pretrained mid-size backbone, strong
     aug, EMA, weight decay, 12 epochs, early stop on label-OOF.
F-13 Site / scanner shift (16 sites; headers alone 0.598 AUC [W]) ->
     site-grouped folds, per-series intensity windowing, intensity aug.
F-14 Duplicate / same-patient studies across folds -> dedup groups.
F-15 Hidden test prevalence differs from train -> AUC is
     prevalence-invariant per label; do not tune thresholds.
F-16 Runtime > 9 h -> producer/consumer decode, time guard with
     degradation ladder, incremental submission.csv.
F-17 GPU memory -> checkpointing, micro-batch 4, bf16; profile in the first
     h100-debug job before full runs.
F-18 Data purged again from scratch (happened 2026-10-04) -> keep labels,
     folds, configs in git; cache + checkpoints copied to SDA/home; a cron
     `touch` is NOT a compliant workaround -- use SDA.
F-19 Time runs out (deadline 2026-10-22) -> R5; first scored submission
     by 2026-10-17; deferred list S16.
F-20 Environment drift (local 3.14 vs Kaggle image Python) -> code avoids
     3.14-only syntax; wheels built for the Kaggle Python version.
F-21 External data / model rules violated (LLM weights, public labels) ->
     T-RULES-2 before using any of them in a submission.
F-22 Label-OOF AUC optimism (agreement with labeler, not truth) -> always
     report gold-OOF beside it.
